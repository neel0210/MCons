## Consolidated behaviour

- **Sidebar/nav (order):** DISCOVER — Home, Icon Packs, Favorites, Apply Icon, Batch Apply, Pack Builder; PREFERENCES — Updates, Settings, About. (See ContentView for shortcuts/badges; Updates shortcut duplicates Apply Icon's Cmd+4.)
- **Settings toggles/defaults:** `defaultIconSize` 1024 (512/1024/2048) — actually consumed by `prepareIconImage`; `showIconNames` true, `autoRefreshFinder` true, `recentFolderLimit` 10 (5–25 step 5) — stored but not consumed elsewhere (see above).
- **PackBuilder steps:** name/description → emoji (first 8 of 15) + accent → add icons (picker/drop, svg/png/jpg/jpeg/icns/tiff) → validate (name + ≥1 icon + slug) → write `<slug>/metadata.json` + copy files to `~/Library/Application Support/MCons/CustomPacks/<slug>` → refresh packs → alert with View-in-Packs.
- **BatchApply flow:** add folders (picker multi / drag-drop, dedup, dirs only) → pick one icon (sheet over all packs) → optional tint → Apply → sequential per-folder `applyAtomicOperation`, per-folder Pending/Applied/Failed, progress count, final attempt-count message.
- **Favorites persistence:** `UserDefaults` key `MCons_Favorites`, `[String]` of `FolderIcon.id`; `Set<String>` in memory; toggled from IconCell hover-star, detail/Favorites action bars, All-Icons context menu; `favoriteIcons()` = filter of cached packs' icons; no ordering, no sync, no cap.
- **Updater flow:** silent check on launch + on Updates appear; manual Check; compare vs `CFBundleShortVersionString`/`CFBundleVersion`; if newer → changelog sheet flag (only when non-silent) + Install (direct zip via `ditto`/`xattr`/relaunch, or terminal 1-liner fallback). Endpoints: `api.github.com/repos/neel0210/MCons/releases/latest`, `raw.githubusercontent.com/neel0210/MCons/main/install.sh`, fallback zip `github.com/neel0210/MCons/releases/download/<tag>/MCons-v1.0.4-release.zip`.
- **MenuBar behaviour:** 290pt popup, drop/browse a folder, 1-click apply first 8 favourites, pick from first 3 recents, open main window, quit. No icon picking, no tint, no undo.
- **IconApply undo/history:** no custom history; single AppKit `UndoManager` chain per apply (undo restores prior icon — or resets if none — and original name, then registers the redo). Undo is only reachable via menu Cmd+Z / Shift+Cmd+Z; BatchApply passes the same environment undo manager (so its applies also register undo, one per folder, sequentially).

## Rust-port flags — pure Rust vs AppKit/objc2 needed

- **Pure Rust (std + crates):** pack discovery + `metadata.json` (serde_json), slug regex, version compare, GitHub API + zip download (reqwest), unzip (zip crate), file copy/rename/create, folder mtime touch (Finder refresh), `UserDefaults` replacement — note `UserDefaults` is a plist at `~/Library/Preferences/<bundle-id>.plist`; Rust must read/write that plist (or use `defaults` CLI) to stay compatible, incl. `MCons_Favorites`, the 4 settings keys, and `mcons_sec_bookmark_*` blobs. Image decode/resize/PNG (image crate), SVG rasterisation (resvg/usvg — replaces CoreSVG/NSImage SVG loading; note MAC branch fixed Marvel SVGs for a 10MB CoreSVG parser limit — re-check sizes in resvg), hex-colour parsing, tint (pixel math, `sourceAtop` blend), trim-transparent-bounds + 0.96-fill scaling, folder-shape rendering (pure 2D drawing, e.g. tiny-skia).
- **Needs AppKit/Foundation via objc2 (or subprocess):** the core feature — `NSWorkspace.setIcon` / `setIcon(nil)` (no public file-level API writes the Finder icon; the `.DS_Store`/`Icon\r` resource-fork path is undocumented — do not reimplement by hand); `NSWorkspace.icon(forFile:)` / `icon(for:.folder)`; `NSImage`/`NSBitmapImageRep`/`NSGraphicsContext` if keeping the native imaging path; security-scoped bookmarks (`NSURL.bookmarkData/resolvingBookmarkData`, `startAccessingSecurityScopedResource`) — required only if the Rust app ships sandboxed; otherwise plain paths work and bookmarks can be skipped; `NSOpenPanel`/`NSSavePanel`, `NSAlert`, `NSPasteboard` (Finder service + copy), `NSApp` activation / window management, `MenuBarExtra`/status item, `UndoManager` (or reimplement undo stack in Rust — recommended, since the Swift one is just a single register-undo/redo pair per apply).
- **No SwiftUI equivalent in Rust:** entire UI (NavigationSplitView, sheets, drag-drop, `MenuBarExtra`, SF Symbols, materials, springs) must be rebuilt — realistic options: egui/iced (cross-platform, restyle JetBlack manually, no SF Symbols — bundle icons), Tauri/wry (web UI), or AppKit via objc2 (native panels/menus, most fidelity, most FFI work). Animations/springs are cosmetic constants, portable as numbers.
- **Subprocess calls to keep as-is:** `/usr/bin/iconutil -c icns` (ICNS export; callable from Rust via `std::process::Command`), `/usr/bin/ditto -x -k`, `/usr/bin/xattr -cr`, `/bin/sh` relaunch script, `curl …/install.sh | bash` terminal fallback.
- **Porting traps:** (1) `defaultIconSize` is read as `double` — a missing key returns 0.0, hence the `>0 ? … : 1024` fallback; (2) `thumbnailImage(size:)` ignores its argument (always 128); (3) `prepareIconImage` pixelDim is `max(2048, min(srcMax,4096))` while point size is `max(defaultSize,1024)` — don't conflate; (4) stale hardcoded fallback zip tag `v1.0.4`; (5) Updates shortcut duplicates Apply Icon's Cmd+4; (6) `glassMorphism(blur:)` ignores `blur`; (7) `cardLift` default accent `#6C5CE7` vs modifier default `#6366F1`; (8) `customImageURL` / `showFolderPicker` state in IconApplyView is declared but unused; (9) BatchApply success message counts attempts, not successes; (10) rename of `.app` targets appends `.app` in two places (AppState + FolderService) — keep both or one will regress.
